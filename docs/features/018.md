# PWA 홈 화면 앱 설치

<!-- 웹 앱을 PWA로 구성하여 홈 화면 아이콘 1탭으로 접근 가능하게 만드는 기능 -->

## Problem

크루원들이 운동 인증을 올리려면 매번 브라우저를 열고 URL을 찾아 접속해야 한다. 주 3~4회 반복되는 core loop에서 "찾고 누르는" 과정이 실제 마찰로 작용하고 있다. 카카오톡은 홈 화면 아이콘 1탭이면 열리는데, Health Zzang은 브라우저 → URL 찾기 → 접속으로 2단계 더 불편하다.

## Value

PWA로 홈 화면에 아이콘을 추가하면 카카오톡과 동일한 1탭 접근이 된다. 주소 표시줄이 사라져 앱처럼 보이고, "최소 마찰 (NON-NEGOTIABLE)" 원칙에 직접 부합한다. PROJECT.md의 assumption에서도 "PWA 등으로 앱 유사 경험 제공"을 대응 방안으로 명시해두었다.

## Solution

Next.js 내장 PWA 지원을 활용하여 웹 앱을 설치 가능한 PWA로 구성한다:

1. **manifest.ts** — 앱 이름, 아이콘, standalone 모드, 테마 색상 정의
2. **앱 아이콘** — 192x192, 512x512 PNG
3. **설치 안내 배너** — 웹 브라우저로 접속 시 상단에 표시, PWA로 이미 설치된 상태면 숨김
4. **설정 탭 설치 버튼** — 배너를 닫은 후에도 설정에서 설치 가능
5. **플랫폼별 분기 안내:**
   - Android Chrome: `beforeinstallprompt` 이벤트로 커스텀 설치 버튼 → 1탭 설치
   - iOS Safari: "공유(□↑) → 홈 화면에 추가" 단계별 가이드 표시
   - iOS 비-Safari: "Safari에서 열어주세요" 한 줄 안내

## Scope

**Includes:**
- `src/app/manifest.ts` — name, short_name, display: "standalone", icons, theme_color, background_color, start_url
- 앱 아이콘 2종 (192x192, 512x512 PNG)
- 설치 안내 상단 배너 컴포넌트 (웹 브라우저 접속 시에만 표시)
- 배너 닫기(X) 시 localStorage로 일정 기간 재표시 방지
- PWA standalone 모드에서는 배너 숨김 (`display-mode: standalone` 미디어 쿼리)
- 설정 탭 안에 앱 설치 버튼/안내 섹션
- Android: `beforeinstallprompt` 이벤트 캡처 → 커스텀 설치 버튼
- iOS Safari: 공유 → 홈 화면에 추가 단계별 가이드 UI
- iOS 비-Safari (Chrome, 카카오톡 인앱 등): "Safari에서 열어주세요" 한 줄 안내
- `<meta name="apple-mobile-web-app-capable">` 등 iOS PWA 메타 태그

**Excludes:**
- Service Worker (오프라인 캐싱, 백그라운드 동기화)
- 푸시 알림
- App Store / Play Store 배포
- 복잡한 딥링크 (iOS 비-Safari → Safari 자동 전환 등)
- 스플래시 스크린 커스터마이징
