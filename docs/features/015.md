# 피드 무한 스크롤 (Infinite Scroll)

## Problem

현재 피드가 한 번에 전체 데이터를 로드. 시즌 진행에 따라 데이터가 수백 건 이상 쌓이면:
- 초기 로딩 시간 증가 (모든 워크아웃 + 미디어 presigned URL 생성)
- R2 presigned URL 생성이 N건마다 1회 → O(N) 지연
- limit으로 자르면 초기 기록 누락 (방금 발생한 버그)

## Solution

### 아키텍처

```
초기 로드 (SSR)           스크롤 추가 로드 (CSR)
┌─────────────┐          ┌──────────────────┐
│ Server      │          │ Client           │
│ Component   │──20건──▶ │ IntersectionObs  │
│ (page.tsx)  │          │ + fetch /api/feed│
└─────────────┘          └───────┬──────────┘
                                 │ cursor 기반
                         ┌───────▼──────────┐
                         │ GET /api/feed     │
                         │ ?cursor=...       │
                         │ &limit=20         │
                         │ &member=...       │
                         └──────────────────┘
```

### API 설계

**`GET /api/feed`**

| 파라미터 | 타입 | 설명 |
|---|---|---|
| `cursor` | string (optional) | 마지막 항목의 `{date}_{id}` (없으면 최신부터) |
| `limit` | number | 기본 20, 최대 50 |
| `member` | string (optional) | 특정 크루원 ID 필터 |

**Response:**
```json
{
  "items": [
    {
      "id": "uuid",
      "date": "2026-10-05",
      "note": "...",
      "nickname": "이현규",
      "userId": "uuid",
      "media": [{ "url": "presigned...", "type": "photo" }],
      "taggedNames": ["전상민"]
    }
  ],
  "nextCursor": "2026-10-01_uuid-xxx" | null,
  "hasMore": true
}
```

**Cursor 구조**: `{date}_{id}` — date DESC 정렬에서 cursor 이후 항목을 가져옴.
- `WHERE (date < cursorDate) OR (date = cursorDate AND id < cursorId)`
- date가 같은 항목이 여러 개일 수 있으므로 id로 tiebreak

### 클라이언트 동작

1. **초기 렌더**: Server Component에서 최신 20건 fetch → FeedContent에 전달
2. **스크롤 감지**: 피드 하단에 sentinel `<div>` 배치, `IntersectionObserver`로 관찰
3. **추가 로드**: sentinel이 뷰포트에 들어오면 `/api/feed?cursor=...` fetch
4. **배지 필터 연동**: member 배지 선택 시 cursor 리셋, 해당 member로 재조회
5. **로딩 표시**: 추가 로드 중 스피너 표시
6. **종료**: `hasMore: false`이면 "모든 기록을 불러왔습니다" 표시, observer disconnect

### 주차 구분선 처리

FeedView가 주차 구분선을 렌더링하는데, 추가 로드 시 이전 배치의 마지막 주차를 기억해야 함:
- `lastWeekLabel` state를 유지
- 새 배치 첫 항목의 주차와 비교하여 구분선 삽입 여부 결정

### 에러 핸들링

- 네트워크 에러 → "다시 시도" 버튼
- R2 presigned URL 만료 → 화면에 보이는 항목은 1시간 내로 충분
- 빈 응답 → "모든 기록을 불러왔습니다"

## Scope

**Includes:**
- `GET /api/feed` cursor 기반 API
- FeedContent를 초기 SSR + 추가 CSR 하이브리드로 변경
- IntersectionObserver 기반 무한 스크롤
- 배지 필터 연동 (member 변경 시 리셋)
- 로딩/종료/에러 상태 UI
- 주차 구분선 연속성

**Excludes:**
- 가상 스크롤 (virtualization) — 현재 규모에서 불필요
- 캐싱 (SWR/React Query) — 추후 필요 시
- Pull-to-refresh
