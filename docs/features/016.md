# 서버사이드 영상 압축 (GitHub Actions)

## Problem

클라이언트 FFmpeg WASM은 모바일 Safari에서 50MB+ 영상 처리 시 메모리 부족으로 실패. 4K 60fps 영상(10초 = 40~110MB)을 올릴 수 없음.

## Solution

클라이언트는 원본을 그대로 R2에 업로드. GitHub Actions 워크플로가 비동기로 ffmpeg 압축 후 R2에 덮어쓰기.

### 아키텍처

```
클라이언트                    GitHub Actions
    │                              │
    ├── 원본 → R2 업로드           │
    ├── /api/workout 저장          │
    │   └── dispatch 트리거 ───────┤
    │                              ├── R2에서 원본 다운로드
    │                              ├── ffmpeg 압축 (720p, 1Mbps)
    │                              ├── 압축본 → R2 덮어쓰기
    │                              └── DB media.size_bytes 업데이트
    │                              │
    └── 피드: 원본 즉시 → 압축본 자동 교체
```

### GitHub Actions 워크플로

트리거: `workflow_dispatch` with inputs (media r2_keys, workout_id)
또는: `/api/workout` 성공 후 `POST /repos/{owner}/{repo}/dispatches` 호출

워크플로 내용:
1. R2에서 원본 다운로드 (aws s3 cp)
2. ffmpeg -i input -vf scale=720p -b:v 1M -c:a aac output.mp4
3. 압축본 R2 업로드 (원본 key 덮어쓰기)
4. Supabase DB의 media.size_bytes 업데이트

### 클라이언트 변경

- 클라이언트 FFmpeg WASM 압축 제거 (import 삭제)
- 파일 크기 제한 해제 (어떤 크기든 업로드 가능)
- 영상은 원본 그대로 R2 presigned URL로 PUT
- 업로드 진행률만 표시

## Scope

**Includes:**
- `.github/workflows/compress-video.yml` — ffmpeg 압축 워크플로
- `/api/workout` POST에서 영상이 있으면 dispatch 트리거
- 클라이언트 크기 제한 해제
- 클라이언트 FFmpeg WASM 코드 제거
- presigned URL 만료 시간 연장 (대용량 업로드용)

**Excludes:**
- 실시간 압축 진행률 (비동기이므로)
- 압축 실패 알림 (원본이 이미 보이므로 무해)
