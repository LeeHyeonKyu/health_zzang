# 클라이언트 영상 압축

## Problem

크루원이 모바일에서 촬영한 영상이 10초에 40MB+. 현재 20MB 제한으로 대부분의 영상 업로드 실패. 영상 인증이 사실상 불가능.

## Value

운동 영상을 자유롭게 올릴 수 있어야 인증의 신뢰도와 동기부여가 올라감. "사진만 올려야 한다"는 제약은 사용성을 크게 떨어뜨림.

## Root Cause

스마트폰 기본 카메라는 4K 60fps + HEVC로 촬영 → 10초에 40~100MB. 서버에서 압축하면 인프라 비용 발생 (NON-NEGOTIABLE 위반). 클라이언트에서 압축해야 함.

## Solution

업로드 전 브라우저에서 영상을 re-encoding:

### 접근 방식 비교

| 방식 | 장점 | 단점 |
|---|---|---|
| **MediaRecorder API** | 네이티브, 추가 다운로드 없음, 빠름 | 코덱/해상도 제어 제한, iOS 호환성 불확실 |
| **FFmpeg WASM** | 강력한 코덱/해상도 제어 | 25MB+ 초기 다운로드, 느림, 메모리 사용 큼 |
| **Canvas + captureStream** | 네이티브 | 오디오 별도 처리 필요, 복잡 |

### 채택: FFmpeg WASM (@ffmpeg/ffmpeg)

이유:
- 해상도(720p)/비트레이트(1Mbps) 정밀 제어 가능
- 오디오 포함 처리
- 입력 포맷 무관 (HEVC, H.264 등 모두 처리)
- 초기 다운로드는 한 번만 (캐시됨)

### 압축 스펙

| 항목 | 값 |
|---|---|
| 최대 해상도 | 720p (1280×720) |
| 비트레이트 | 1 Mbps |
| 오디오 | 128 kbps AAC |
| 출력 포맷 | MP4 (H.264 + AAC) |
| 예상 크기 | 10초 → ~1.5MB, 1분 → ~8MB |

### 압축 흐름

1. 영상 파일 선택
2. 크기 확인: 5MB 이하 → 그대로 업로드 (압축 불필요)
3. 5MB 초과 → 압축 시작, 프로그레스 바 표시 ("영상 압축 중... 40%")
4. 압축 완료 → 원본 대비 크기 표시 ("40MB → 1.5MB로 압축됨")
5. 압축 실패 시 → 원본으로 업로드 시도 (20MB 이내면)

## Scope

**Includes:**
- @ffmpeg/ffmpeg, @ffmpeg/util 패키지 설치
- 영상 압축 유틸 (`src/lib/video-compress.ts`)
- 업로드 폼에서 자동 압축 + 프로그레스 표시
- 압축 결과 크기 비교 안내
- 5MB 이하 영상은 스킵

**Excludes:**
- 서버 사이드 압축
- 이미지 압축 (이미 Canvas로 구현됨)
- 영상 편집 (트리밍 등)
